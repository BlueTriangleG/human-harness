# 感官事件约定：HH 和角色的感官脚本之间

归闸门（消费它的代码：src/gate/、src/brain.ts 的 fromSenses、控制台的闸门页）。改约定先改这份，再改代码。

## 1. 交法

- 角色的感官脚本用控制命令 `{"cmd": "sense", "text": …, "events": […]}`（`hh sense`）交给 HH。HH 回 `{"status": "ok"}` 就算接到手了：落库、由闸门负责，脚本不用再等别的确认。
- HH 认 `events` 里每一项的字段。`text` 只给旧的文本格式兜底，见第 6 节。
- 角色自己留一份事件日志，每行一个事件（字段同第 2 节），再加 `t`（本地时间「YYYY-MM-DD HH:MM:SS」）和 `ts`（秒）。日志在哪写在实例配置 `senses.logFile`，相对工作区；空就是没有这份日志，重判（`hh gate replay`）和规则试算（what_reaches_me 的 try）不做。

## 2. 事件的字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| src | 字符串 | 是 | 来源代号，要在角色的通道表里（第 3 节）。不在表里的交规则判 |
| id | 字符串 | 是 | 同一个上游事件不变。HH 按 id 去重（HH 自己的 plain、hh-quota 除外）。怎么算由角色定 |
| text | 字符串 | 是 | 给角色看的那一行，不带「- [src id=]」前缀 |
| do | 字符串 | 否 | 怎么处理的提示，HH 原样接在后面 |
| body | 字符串 | 否 | 长正文 |
| conv | 字符串 | 聊天来源要写 | 会话名：群名，或私聊对方的名字 |
| sender | 字符串 | 群消息要写 | 谁说的 |
| isGroup | 布尔 | 聊天来源要写 | 没写时 HH 按偏严处理：@ 当群里的算，标题认出来的人当「只按显示名认的」 |
| mentionsMe | 布尔 | 否 | 有人 @ 角色。平台自己的 @ 标记由脚本认；没写时 HH 只在原文里找「@名字」（名字来自实例配置） |
| unread | 数字 | 否 | 这一条之前还有几条没看到 |
| alarm | 布尔 | 否 | 要角色本人处理。只有通道表里 probe 的来源写了才算数 |
| system | 只认 true | 否 | 脚本自己生成的系统提示（不是谁发来的话）。带它时不写 conv、sender、isGroup |

`urgent` 是 HH 自己的额度提醒用的，脚本写了也不认。字段类型不对的那一个字段丢掉，其余照用。

## 3. 通道表（实例配置 `senses.sources`）

每一类是一个来源名的数组，一个来源可以在几类里。框架的默认全空。

| 类 | 是什么 | HH 怎么对待 |
|---|---|---|
| chat | 聊天 | 按名单认人；陌生人私聊走规则；控制台遮访客的原文；每日总结提名「反复来私聊、认不出是谁」的会话 |
| public | 公开场合别人对角色说的（评论回复之类） | 交规则判；控制台不遮；判过以后送去时带上「怎么回」那句 |
| probe | 角色自己的探针 | 带 `alarm` 或标签以「·要你处理」结尾（英文 `·needs you`，每种语言的都认）的一律直达 |
| always | 一律直达 | 不判 |
| hands | 帮手的回报 | 交帮手那条路 |

- 表里没有的来源交规则判；控制台把它当聊天来遮（宁可多遮：新角色的新来源还没标时不漏）。
- HH 自己的来源不在表里，写在代码里（src/gate/sources.ts）：`plain`（没有事件行的一整段文字，一律直达）、`hh-quota`（hhd 自己的额度提醒，交规则）。
- 读表只经 src/gate/sources.ts，别处不再写来源名单。

## 4. 安全规矩（过去几轮复核定下的，改代码时不能松）

1. 只有 probe 来源的 `alarm` 和「·要你处理」（每种语言的写法）算数：聊天来源里谁都能打出这几个字、把群名改成这样。
2. 明确是私聊（`isGroup: false`）的「@名字」不插队，走私聊的规则。
3. 群名被认成某个人时一律当没核实（按显示名认的）：群名谁都能改。
4. 好友申请的标题是对方自己起的昵称，认出来也只算显示名。
5. `system` 只认布尔的 true，写成字符串、数字的不算。

## 5. 名字

角色的名字、主人的名字从实例配置取（`names`，经框架的 `roleNames`）。脚本不用把名字写进事件。

## 6. 旧的文本格式（兼容层）

第一个角色的脚本早先只送文本，比如「- [src id=…] 会话：[N条]…」，正文块用「┄┄┄┄ 正文 ┄┄┄┄」包起来（英文 `┄┄┄┄ body ┄┄┄┄`）；正文块的开头、事件后面要确认的那一行、探针要本人处理的标签尾巴，脚本按角色的语言写，闸门每种语言的都认（语言包 gate.parse）。还有几处平台写法要从文本里拆：私信标题里的「私信你」、通知里的 @ 标记、好友申请那句、探针的「·要你处理」标签。

这些解析要挪进 src/legacy/，由实例配置的开关 `senses.legacyText` 打开；框架默认关，只有第一个角色的配置写 true。挪进去时记下「这条靠拆文本」的次数，连着 7 天是 0 就删掉这个模块（单开一个小范围）。

新角色的脚本只送第 2 节的字段。
