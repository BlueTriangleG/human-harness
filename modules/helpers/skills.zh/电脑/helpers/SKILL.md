# 帮手（helpers）

## 是什么
一个帮手是一个在后台跑的 Claude Code 会话，有自己的名字和工作目录。你派活给它，它自己干；干完一轮（回完话）、出错、额度用完、或者很久没动静，感官会叫醒你，它最后回你的话直接附在叫醒里。会话记得上下文，下次再 send 是接着说。

## 命令
- `helper send <名字> "话" [--dir 目录] [--add-dir 目录]… [--model sonnet|haiku|opus|default] [--light]`
  - 没有这个名字：新开一个，工作目录默认是任务目录下的 `<名字>`，`--dir` 指定别的。
  - 它空闲着：接着说。
  - 它正在干活：插话，它做完下一步就看到。
  - `--model`：之后每轮用哪个模型；换模型那一轮整段缓存要重写，长期换不如新开一个。
  - `--light`：只改代码、跑小测试的轻活，不做音视频处理、不装东西、不开浏览器。
- `helper show <名字> [轮数|all] [--process|--steps|--full]`：默认只看它最后回你的那条；`--process` 看每一步做了什么，`--steps` 再带上每一步的结果，`--full` 不截断。
- `helper ls`：所有帮手，在干活还是空闲、目录、最后一句。
- `helper stop <名字>`：叫停（像按 Esc），想继续就再 send。
- `helper allow <名字> "规则"`：放行一类它被拦下的操作，比如 `"Bash(npm install:*)"`，再 send 让它继续。
- `dispatch <目录> <一句话说明> -- <命令…>`：不用帮手、只跑一条长命令时用，跑完叫醒你。

## 派活的规矩
- 新开一个会话之前要过负载闸：电脑危险或余量不够时这轮不开，先腾地方或者等一等。已经在干活的会话插话不拦。
- 派活时会自动附上你笔记里和这件事相关的几页，附了哪几页写在命令的输出里。
- 一件事一个会话，名字起得能看出是什么事。
- 写清楚要它交什么、怎样算做完；大的活让它分步交。

## 验收
- 它说做完了不等于做对了：看结果、跑一下、对照你要的标准。
- `helper show <名字> --process` 看它是怎么做的，有没有跳过、蒙混。
- 合格了再告诉需要知道的人；不合格就接着 send，说清楚哪里不对。

## 常见的坑
- 同时开好几个吃内存的帮手（视频、渲染），电脑会被挤到危险，帮手会被自动减负关掉。重活一件一件来。
- 插话只在它下一步做完时才看到；很急就先 stop 再 send。
- 它被权限拦下时会停在那里等，用 `helper allow` 放行，不要让它绕过去。
- 换模型会重写缓存，别来回换。
