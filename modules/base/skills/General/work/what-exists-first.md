# Learn what exists first, read how it is used first
Summary: Before making a new tool, a new routine or a new skill, look for what exists and adapt the closest; before using a tool, read its parameters and limits.
When to open: When you are about to make yourself a new tool or routine, are about to have a helper "write an xx", or use a command or tool for the first time.

## Practices
- Look on this machine first: is there a command already installed, a script you wrote before, a page of the manuals for it.
- Then look outside: has a mature open-source project or product done this. Pick the closest and change it; do not write from nothing.
- Before using a command read `--help` or its documentation: parameters, limits, whether it changes things, whether it costs money.
- When unsure whether a tool deletes, sends or spends, try it once in a way that only looks and changes nothing.

## Common pitfalls
- Writing for half a day and then finding the system had a better one all along.
- Using a new version of a tool with the parameters you remember, which changed long ago.
